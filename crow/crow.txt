1/basic routing and links
    -Route::get('/', function () {
       return view('home');
    });
you can also use that to return variable and arrays, for when building an api
it is recommended to give routes names
    -Route::get('/', function () {
       return view('home');
    })->name('home');
there is a shortcut
    -Route::view('/', 'home')->name('home');
if home is inside a directory inside views, let's say mypages then the return is gonna be mypages.home
you can also pass arrays of data in the return or right after the page name, remmeber arrays and like this -['stuff'=>25]
then call it in blade like {{$stuff}}
links are like normal html or preferably:
    -href="{{ route('home') }}"

rerouting is done like this: return redirect()->route('home');


you can also do this instead of writing logic in web
    Route::get('/', [controller_name::class, 'method_name])->name('home');
    then write everything else in the controller class right until the return view thing and including the arguments
    also php artisan make:controller


2/components:
make a component directory inside your views directory and just write your component
you can use it like this <x-mycomponent/>
you can have slots like {{$slot}} and custom ones like {{$title}}
you use them like this:
    -<x-mycomponent>
        <x-slot:title>
            <h1>welcome to the HOME/CROW page</h1>
        </x-slot:title>
        <p>other main stuff</p> //this being the default {{$slot}}
    </x-mycomponent>
in order to merge html options like classes, href and all you add this inside the component
    -{{ $attributes }}
if you need to merge classes and you don't want duplications and weird css error do this
    -{{ $attributes->merge(['class' => 'put your tailwind here']) }}

--AUTHENTICATION
Auth::login($user) or just array of user, USE THIS WHEN FIRST CREATING A USER
Auth::attempt($user) or just an array of user, USE THIS WHEN LOGGING IN SOMEONE
    it returns true or false so if false throw a validation exception like this
    -if ($authed == false){
            throw ValidationException::withMessages([
                'password'=>'wrong password mate'
            ]);
    }
    also make sure to do this for security: request()->session()->regenerate()
Auth::logout is for logging out the current user

    ---GUARDS
    GUARDS are a way to let create models/databases that you can log in other than users

    first create your model and make sure it extends autheticatable:
        -use Illuminate\Foundation\Auth\User as Authenticatable;
        -class mymodel extends Authenticatable

    second in config/auth.php add another guard and provider under the already existing ones, they are elements in an array
        -'guards' => [
                    'web' => [
                        'driver' => 'session',
                        'provider' => 'users',
                    ],
                    'grim' => [ //grim is just a random name i picked
                        'driver' => 'session',
                        'provider' => 'killers',
                    ],
        ],'providers' => [
                    'users' => [
                        'driver' => 'eloquent',
                        'model' => env('AUTH_MODEL', App\Models\User::class),
                    ],
                    'killers' => [
                        'driver' => 'eloquent',
                        'model' => env('AUTH_MODEL', App\Models\mymodel::class),
                    ],
        ]

    third just use your Auth façade like you do normally just add guard('grim') like Auth::guard('grim')->login() or Auth::guard('grim')->check()
    in blade it's auth('grim') and guest('grim')

    --IMPORTANT
        -attempt needs a password column in the table
        -to do global guest you need custom logic
        -don't forget throwing validation exception if an already logged in user tries to log in or sign up, especially if you have multiple guards


    --Authorization
    well you can do it inline, middlewear is just what gets executed between receiving a request and serving a page afterall
    tools like is/isnot and check and ->user are useful
    policices exist
    but the main auz guy is the gates, define then is serviceprovider boot and refrence them wherever ya want
        -Gate::define('edit_victim', function($killer, $victim){
                return $victim->serialkillers->is($killer);
            });
    it has to return true or false, can be used like gate::authorize('name_of_gate', args), allows, denies
    the $user argument gets passed auto in web no need to write it in args
    ---if ya are using a guard do it like this
    -------Gate::forUser(Auth::guard('grim')->user())->authorize('edit_victim', victim::find($id))
    some useful things like can directive and can method can also be used but only with web guard, just use if and logic for rest
    there is also the middlewear shorthand that can check if auth, like middlewear('auth') if fails it looks for login named route
    for guards it's middlewear('auth:grim') and if fails looks for grim.login
    there is also ->can('gate_name', args) that can be used inline, usually args are strings 'id' for example coming from the {id} thing
